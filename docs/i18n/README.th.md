# AI Page Translator — แปลเว็บด้วย AI ของคุณเอง

**แปลหน้าเว็บใดก็ได้เป็นภาษาของคุณด้วยผู้ให้บริการ AI ที่คุณเลือก — ไม่มีเซิร์ฟเวอร์ ไม่มีบัญชี ไม่มีการติดตาม และไม่คิดค่าบริการตามคำ**

`Manifest V3` · `ไม่ต้อง build` · `JavaScript ล้วน` · `เวอร์ชัน 1.3.1` · `22 ภาษา`

ไฟล์นี้เป็นฉบับแปลภาษาไทยของ [README ต้นฉบับภาษาอังกฤษ](README.md) หากมีความแตกต่าง ให้ยึดฉบับภาษาอังกฤษเป็นหลัก

AI Page Translator เป็นส่วนขยายเบราว์เซอร์สำหรับ **Brave** และเบราว์เซอร์อื่นที่ใช้ Chromium คุณเป็นผู้เลือกผู้ให้บริการเอง: คีย์ Google Gemini ฟรี จุดเชื่อมต่อใดก็ได้ที่รองรับ OpenAI (OpenRouter, Groq, NVIDIA, OpenAI…) หรือโมเดลท้องถิ่นทั้งหมดผ่าน **Ollama** ส่วนขยายจะแปลหน้าที่คุณกำลังอ่านในตำแหน่งเดิม โดยคงเลย์เอาต์ ลิงก์ และการจัดรูปแบบไว้

ไม่มีข้อความใดผ่านบริการแปลตัวกลาง คีย์ API ไม่ออกจากเบราว์เซอร์ ไม่มีเครื่องมือวิเคราะห์ใด ๆ และหากใช้ Ollama ข้อความจะไม่ออกจากเครื่องของคุณเลย

> **สถานะ:** เวอร์ชัน 1.3.1 · การทดสอบอัตโนมัติ 95 รายการ · การตรวจสอบ 12 จุด · ไม่มีเทเลเมทรี ไม่มีโค้ดจากระยะไกล

## ทำไมต้องมีตัวแปลอีกตัว?

ตัวแปลหน้าเว็บส่วนใหญ่ส่งทีละประโยค ผลลัพธ์จึงอ่านเหมือนกองประโยคมากกว่าหนึ่งหน้า: บริบทหายไป คำศัพท์ไม่สม่ำเสมอ ลิงก์ตัดประโยคออกเป็นสองท่อน และภาษาเป้าหมายรับลำดับคำของภาษาต้นฉบับมาด้วย

ส่วนขยายนี้แปลเป็น**บล็อก** ไม่ใช่โหนดข้อความ:

```
The <a>new privacy policy</a> takes effect <strong>immediately</strong>.
```

ทั้งบล็อกถูกส่งเป็นหน่วยเดียว โดยมาร์กอัปแบบอินไลน์ถูกแทนที่ด้วยโทเคนที่มีหมายเลข:

```
The <t1>new privacy policy</t1> takes effect <t2>immediately</t2>.
```

`<tN>…</tN>` หมายถึงเนื้อหาแบบอินไลน์ที่เป็นส่วนหนึ่งของประโยค (ลิงก์ การเน้น span) และ `<vN/>` หมายถึงเนื้อหาที่ห้ามแปลเด็ดขาด (โค้ด รูปภาพ ตัวควบคุมฟอร์ม วิดเจ็ต) โมเดลย้ายโทเคนได้ จึงสร้างประโยคภาษาปลายทางที่เป็นธรรมชาติ**รอบ**ลิงก์ แทนที่จะติดอยู่กับลำดับคำแบบอังกฤษ

ขากลับ คำตอบจะถูกตรวจสอบก่อนแตะหน้าเว็บ โทเคนทุกตัวต้องอยู่ครบ จับคู่ครบ และไม่ซ้ำ คำแปลที่ทำลิงก์หายจะถูกปฏิเสธ ลองใหม่หนึ่งครั้งด้วยคำสั่งที่เข้มขึ้น และถ้ายังไม่ได้ก็ปล่อยไว้ตามเดิม ระบบใช้โหนดองค์ประกอบเดิมซ้ำ `href` ตัวรับฟังเหตุการณ์ และมาร์กอัปที่ซ้อนกันจึงยังอยู่ครบ "แสดงต้นฉบับ" จะคืนโหนดเดิมอย่างแม่นยำ

## ความสามารถ

- **แปลทั้งหน้าในตำแหน่งเดิม** — หัวข้อ ย่อหน้า รายการ ตาราง คำบรรยายภาพ และปุ่ม
- **รักษาลิงก์และการจัดรูปแบบอินไลน์** — ตรวจสอบด้วยโทเคน ลิงก์ที่หายไปจะไม่ถูกนำไปใช้อย่างเงียบ ๆ
- **สไตล์ธรรมชาติหรือตรงตัว** — *ธรรมชาติ* (ค่าเริ่มต้น) เขียนใหม่เหมือนนักเขียนเจ้าของภาษา ส่วน *ตรงตัว* เกาะข้อความต้นฉบับในหน้าด้านเทคนิค
- **คู่มือสไตล์แยกตามภาษา** — คำแนะนำเฉพาะสำหรับเปอร์เซีย อาหรับ อูรดู และฮิบรู พร้อมคู่มือทั่วไปสำหรับอีก 18 ภาษา
- **แก้ไขอักขรวิธีแบบแน่นอน** — `ی`/`ک` ของเปอร์เซีย ช่องว่างศูนย์ความกว้างใน `می`/`ها`/`تر` และ `، ؛ ؟` ถูกแก้แม้โมเดลพลาด
- **รอบตรวจคุณภาพแบบเลือกได้** — อ่านแต่ละท่อนเป็นคู่ {ต้นฉบับ, คำแปล} จึงแก้ความหมายได้ ไม่ใช่แค่ถ้อยคำ
- **อภิธานศัพท์** — คู่ "คำศัพท์ → คำแปล" ที่โมเดลต้องปฏิบัติตาม
- **เนื้อหาที่ได้รับการป้องกัน** — `<pre>`, `<code>`, URL, อีเมล, `translate="no"`, `contenteditable`, SVG, ตัวควบคุมฟอร์ม และอินเทอร์เฟซของส่วนขยายเองจะไม่ถูกส่ง
- **ป้ายกำกับแอตทริบิวต์** — `alt`, `title`, `placeholder` และ `aria-label` ไปตามช่องทางแยก ด้วยน้ำเสียงแบบป้าย ไม่ใช่ย่อหน้า
- **หน้าไดนามิก** — เนื้อหาจากการเลื่อนไม่สิ้นสุดหรือ SPA ถูกแปลทันทีที่ปรากฏ โดยไม่เกิดลูปของผู้สังเกต
- **ขวาไปซ้ายอย่างถูกต้อง** — `dir` บนแต่ละบล็อกที่แปล `lang` บน `<html>` ไม่พลิกทั้งหน้า และคืนค่าทุกอย่างได้
- **จดจำต่อเว็บไซต์** — จำภาษาเป้าหมายของแต่ละโดเมน และแปลอัตโนมัติเมื่อโหลดได้
- **บริการใดก็ได้ที่มี API** — Gemini, Ollama และจุดเชื่อมต่อที่รองรับ OpenAI เรียกจาก service worker จึงไม่มีปัญหา CORS
- **แคชในหน่วยความจำ ลองใหม่ และแบ่งท่อน** — ข้อความซ้ำส่งครั้งเดียว บล็อกที่ล้มเหลวถูกแบ่งแทนที่จะทำให้ทั้งหน้าล้ม ข้อผิดพลาด 429/5xx ถูกลองใหม่ด้วยการรอที่เพิ่มขึ้น
- **ไม่ต้อง build** — สคริปต์คลาสสิกธรรมดา โหลดตามเดิม

## การติดตั้ง

1. ดาวน์โหลดที่เก็บนี้ (**Code → Download ZIP** หรือ `git clone`) แล้วเก็บโฟลเดอร์ไว้
2. เปิด `brave://extensions` (หรือ `chrome://extensions`)
3. เปิด **Developer mode**
4. กด **Load unpacked** แล้วเลือกโฟลเดอร์นี้ (โฟลเดอร์ที่มี `manifest.json`)
5. ปักหมุดส่วนขยายหากต้องการให้ป๊อปอัปอยู่ห่างหนึ่งคลิก

ไม่มีขั้นตอน build ติดตั้ง หรือบันเดิล ส่วนขยายอ่านเฉพาะไฟล์ที่ระบุใน `manifest.json` ส่วน `tests/`, `scripts/`, `bench/`, `docs/` และ `.github/` ใช้เพื่อการพัฒนเท่านั้นและไม่ถูกโหลด

ต้องใช้เบราว์เซอร์ Chromium รุ่นใหม่ shadow root แบบปิดจะถูกแปลเมื่อเบราว์เซอร์เปิด API (Chromium 119 ขึ้นไป) ส่วนอื่นทำงานได้ในรุ่นเก่ากว่า

## การแชร์ให้ผู้อื่น

คำสั่ง `npm run release` สร้างแพ็กเกจและวางไฟล์ใน `release/` (โฟลเดอร์นี้ git ไม่ติดตาม):

| ไฟล์ | คืออะไร | วิธีติดตั้ง |
|---|---|---|
| `page-translator-ai-<version>.zip` | ส่วนขยายทั้งหมด ประมาณ 95 KB พร้อม `INSTALL.txt` ข้างใน | แตกไฟล์ → **Load unpacked**; เป็นไฟล์เดียวกับที่ร้านค้ายอมรับ |
| `page-translator-ai-<version>.crx` | แพ็กเกจที่ลงนามแล้ว | ลากไปที่ `brave://extensions` ในที่ที่อนุญาตให้ติดตั้งนอกร้านค้า |
| `page-translator-ai-signing-key.pem` | กุญแจลงนาม | ห้ามแชร์เด็ดขาด; `npm run release` ใช้กุญแจเดิมเพื่อให้ ID ของส่วนขยายคงที่ระหว่างการอัปเดต |

สิ่งที่คุณส่งให้ผู้อื่นจึงเป็นไฟล์เดียว และมีขั้นตอนติดตั้งอยู่ข้างใน

**ข้อจำกัดที่ตรงไปตรงมา:** ส่วนขยายเบราว์เซอร์เป็นโค้ดฝั่งไคลเอนต์ ใครติดตั้งก็อ่านไฟล์เหล่านั้นได้ — `.crx` คือ zip ที่ลงนามแล้ว และส่วนขยายที่ยังไม่แพ็กคือโฟลเดอร์ธรรมดา การแพ็กหรือการทำให้อ่านยากไม่เปลี่ยนข้อเท็จจริงนี้ การย่อโค้ดเพียงทำให้อ่านช้าลง และนโยบายร้านค้าห้ามการทำให้อ่านยาก หากต้องเก็บซอร์สเป็นความลับจริง ทางเลือกเดียวที่สมเหตุสมผลคือย้ายพรอมป์ต์และการเรียกผู้ให้บริการไปยังเซิร์ฟเวอร์ที่คุณควบคุม ซึ่งหมายถึงการทิ้งดีไซน์ "คีย์ของคุณเอง ไม่มีเซิร์ฟเวอร์"

หากต้องการแจกโดยไม่ให้ที่เก็บโค้ด ให้เผยแพร่ zip เป็นรายการ**ส่วนตัวหรือไม่แสดงรายการ**บน Chrome Web Store นี่เป็นวิธีเดียวที่จะติดตั้งได้ในคลิกเดียวสำหรับผู้ใช้ทั่วไป

## การตั้งค่าผู้ให้บริการ

ป๊อปอัปของส่วนขยาย → **Options & settings** หรือ `brave://extensions` → รายละเอียด → ตัวเลือกส่วนขยาย

| ผู้ให้บริการ | จุดเชื่อมต่อ | คีย์ | หมายเหตุ |
|---|---|---|---|
| **Ollama** (ท้องถิ่น) | `http://localhost:11434` | ไม่ต้องใช้ | ฟรีและเป็นส่วนตัวเต็มที่ ติดตั้งจาก [ollama.com](https://ollama.com) แล้วรัน `ollama run llama3` หากได้ 403 ให้เริ่มใหม่ด้วย `OLLAMA_ORIGINS=chrome-extension://*` |
| **Google Gemini** | `generativelanguage.googleapis.com` | คีย์ฟรีจาก [AI Studio](https://aistudio.google.com/app/apikey) | ใช้ ID โมเดลปัจจุบัน เช่น `gemini-2.5-flash` โควตาฟรีเปลี่ยนได้ ตรวจสอบรายการโมเดลของ Google |
| **รองรับ OpenAI** | จุดเชื่อมต่อของคุณ เช่น `https://openrouter.ai/api/v1`, `https://api.groq.com/openai/v1`, `https://integrate.api.nvidia.com/v1` | คีย์ของผู้ให้บริการ | บริการใดก็ได้ที่รองรับ `/chat/completions` โมเดลที่แนะนำในอินเทอร์เฟซเป็นเพียงตัวอย่าง ใช้ ID ที่ถูกต้องจากแค็ตตาล็อกของผู้ให้บริการ |

จากนั้น:

1. เลือก**ภาษาเป้าหมายเริ่มต้น**
2. เลือก**สไตล์การแปล**: *Natural* (แนะนำ) หรือ *Literal*
3. ถ้าต้องการ เปิด **Quality mode** และเพิ่มรายการ**อภิธานศัพท์** บรรทัดละหนึ่งรายการ (`คำศัพท์ → คำแปล`; ใช้ `->`, `=>`, `=` และ TAB ได้ด้วย)
4. ตั้ง**ภาษาต้นฉบับ**เป็น *Auto-detect* หรือเลือกเอง
5. กด **Test connection** แล้ว **Save settings**

หมายเหตุเกี่ยวกับผู้ให้บริการ:

- **การตั้งค่าการคิดของ Gemini เลือกตามรุ่นของโมเดล** 2.5 Flash และ Flash-Lite ทำงานโดยไม่คิด 2.5 Pro ใช้ขั้นต่ำ (128) และ 3.x/4.x ใช้ระดับต่ำ หากโมเดลปฏิเสธการตั้งค่า คำขอจะถูกลองใหม่หนึ่งครั้งโดยไม่มีค่านั้น
- **Ollama** ถูกเรียกด้วยหน้าต่างบริบท 8192 โทเคน โมเดลที่ฝึกด้วยบริบทน้อยกว่าจะยังตัดหน้ายาว — จึงแบ่งหน้าเป็นหน่วยเล็ก ๆ
- **โควตาฟรี** จำกัดอัตรา ส่วนขยายรอและลองใหม่ ไม่ทิ้งข้อความอย่างเงียบ ๆ

## การใช้งาน

- คลิกไอคอน → เลือกภาษา → **Translate this page**
- **Show original / Show translation** ได้ทุกเมื่อ การคืนค่าไม่สูญเสียอะไร
- ชี้เมาส์เหนือย่อหน้าที่แปลแล้วเพื่อดูต้นฉบับ
- คลิกขวา → **Translate this page** หรือ **Translate selection**
- แป้นพิมพ์: `Ctrl+Shift+Y` (`Cmd+Shift+Y` บน macOS) สลับการแปล เปลี่ยนได้ที่หน้าการตั้งค่าแป้นลัดของเบราว์เซอร์
- เมื่อเปิด **Auto-translate** และมีการบันทึกการตั้งค่าเว็บไซต์ หน้าที่ตรงกันจะแปลอัตโนมัติเมื่อโหลด
- การตั้งค่ามีผลกับแท็บที่เปิดอยู่ในการแปลครั้งถัดไป ไม่ต้องโหลดหน้าใหม่

## วิธีการทำงาน

```
DOM ของหน้า
  └─ content script: เก็บหน่วยบล็อก แปลงมาร์กอัปอินไลน์เป็นโทเคน <tN>/<vN/>
       └─ ตัวแบ่ง: 24 หน่วย / 2400 อักขระต่อคำขอ
            └─ service worker: ส่งคำขอไปยังผู้ให้บริการ (ต้นกำเนิดส่วนขยาย ไม่มี CORS)
                 └─ ผู้ให้บริการ: JSON เข้า JSON ออก ID คงเดิม
                      └─ ตรวจสอบ: โทเคนครบ สมดุล ไม่ซ้ำ ID ตรงกัน
                           └─ DOM: ใช้โหนดองค์ประกอบเดิมซ้ำ เขียนเฉพาะข้อความ
                                └─ MutationObserver: แปลเนื้อหาที่เพิ่มเข้ามาทีหลัง
```

การตัดสินใจที่สำคัญจริง:

- **การรับส่งไปยังผู้ให้บริการไม่เคยออกจากบริบทของหน้า** content script ส่งข้อความ `AIPT_FETCH` และ service worker เป็นผู้ส่งคำขอ จุดเชื่อมต่อที่ตั้ง CORS เข้มจึงใช้ได้ตามเดิม service worker ตรวจ `sender.id` ด้วย จึงมีเพียงส่วนขยายนี้ที่ใช้เป็นพร็อกซีได้
- **พรอมป์ต์คือสัญญา ไม่ใช่ความหวัง** ID เข้า ID ออก หนึ่งรายการต่อท่อน แท็กแตะต้องไม่ได้ ตัวเลข URL โค้ดและตัวยึดตำแหน่งคงเดิม ไม่มีคำอธิบายเพิ่ม คำตอบถูกอ่านตาม ID อาเรย์ที่สลับลำดับหรือเสียรูปบางส่วนจึงล้มเหลวอย่างปลอดภัยแทนที่จะทำให้คำแปลเลื่อน
- **แต่ละภาษามีคู่มือสไตล์ของตนเอง** เช่น คู่มือเปอร์เซียกำหนดลำดับคำและกริยาเปอร์เซีย (`بررسی کنید` ไม่ใช่ `بررسی را انجام دهید`) ห้าม `می‌باشد`/`بایستی`/`گردید` ในที่ที่ประโยคธรรมดาเพียงพอ เก็บคำยืมจริงไว้ในอักษรละตินเท่านั้น และแก้เครื่องหมายวรรคตอนกับช่องว่างศูนย์ความกว้าง ตัวอย่าง few-shot แสดงเป้าหมายให้โมเดลเห็น ไม่ใช่เพียงอธิบาย
- **ทิศทางเป็นระดับท้องถิ่น** บล็อกเปอร์เซีย อาหรับ ฮิบรู และอูรดูได้ `dir="rtl"` `<html>` ได้ภาษาเป้าหมาย ส่วนที่เหลือคงรูปทรงเดิม — การพลิกทั้งหน้าเคยทำให้เลย์เอาต์กึ่งกลางและบล็อกโค้ดเสีย ทั้งสองอย่างถูกคืนค่าพร้อมข้อความเดิม
- **ข้อผิดพลาดมองเห็นได้และจำกัดขอบเขต** บล็อกที่อ่านไม่ได้จะถูกแบ่ง หน่วยที่ยังล้มเหลวจะคงภาษาต้นฉบับและรายงานในแถบด้านบน การยกเลิกระหว่างแปลหยุดอย่างสะอาดและไม่ทิ้ง DOM ที่เขียนค้าง

รายละเอียดเพิ่มเติม: [`docs/translation-quality-design.md`](../translation-quality-design.md)

## ความเป็นส่วนตัวและสิทธิ์

| สิทธิ์ | ทำไมต้องใช้ |
|---|---|
| `storage` | เก็บการตั้งค่า คีย์ API อภิธานศัพท์ และการตั้งค่าแต่ละเว็บไซต์ใน `chrome.storage.local` |
| `contextMenus` | เมนูคลิกขวา "แปลหน้านี้ / ส่วนที่เลือก" |
| `tabs` | ส่งข้อความไปยังแท็บที่ใช้งานและเปิดหน้าตัวเลือก |
| `activeTab` | ทำงานบนหน้าที่คุณสั่งแปลเอง |
| `<all_urls>` | ฉีด content script ลงในหน้าที่คุณเข้าชม และให้ service worker เรียกจุดเชื่อมต่อที่ตั้งไว้ได้ |

- คีย์ API เก็บไว้ในที่เก็บภายในเครื่องของเบราว์เซอร์นี้เท่านั้น และส่งไปยังผู้ให้บริการที่คุณเลือกเท่านั้น
- ไม่มีการวิเคราะห์ ไม่มีเทเลเมทรี ไม่มีโค้ดระยะไกล ไม่มีการติดต่อเซิร์ฟเวอร์ผู้พัฒนา และไม่มีบัญชี
- ข้อความทั้งหมดเขียนด้วย `textContent` / `createTextNode` ไม่มี `innerHTML`, `eval` หรือ `new Function` ที่ใดในส่วนขยาย เอาต์พุตของโมเดลไปถึงหน้าได้เพียงเป็นข้อความ และแอตทริบิวต์ถูกจำกัดด้วยรายการอนุญาตคงที่ — `href`, `src` และตัวจัดการเหตุการณ์ไม่ถูกเขียนจากเอาต์พุตของโมเดล
- การตั้งค่าแต่ละเว็บไซต์เขียนโดยตัวเขียนแบบเรียงลำดับเพียงตัวเดียวใน service worker สองแท็บจึงเขียนทับกันไม่ได้
- การตรวจจับภาษาอัตโนมัติส่งตัวอย่างไม่เกิน 600 อักขระไปยังผู้ให้บริการเดียวกัน การเลือกภาษาต้นฉบับเองจะตัดคำขอนี้ทิ้งทั้งหมด

นโยบายความปลอดภัยและวิธีรายงานช่องโหว่: [`SECURITY.md`](../../SECURITY.md)

## ข้อจำกัดที่ทราบ

- **การตรวจสอบโทเคนเข้มงวดโดยเจตนา** โมเดลที่ทำ `<tN>` เสียเป็นประจำจะทำให้ย่อหน้าเหล่านั้นคงภาษาต้นฉบับ (และแจ้งให้ทราบ) แทนที่จะทำลิงก์หาย ใช้โมเดลที่ทำตามเอาต์พุตแบบมีโครงสร้าง *Test connection* จะทดลองประโยคที่มีโทเคน
- **คุณภาพขึ้นอยู่กับโมเดล** โมเดลท้องถิ่นขนาดเล็กใช้ได้แต่ไม่ลื่นไหลเท่า Gemini หรือโมเดลระดับ GPT ชั้นสไตล์ช่วยได้ แต่เพิ่มความรู้ไม่ได้
- **shadow root แบบปิดและ iframe ข้ามต้นกำเนิด** อยู่นอกเหนือความสามารถของส่วนขยาย (ความปลอดภัยของเบราว์เซอร์) shadow root แบบเปิดและเฟรมต้นกำเนิดเดียวกันได้รับการรองรับ
- **คอนเทนเนอร์ผสมที่มีข้อความลอย** (`<div>ข้อความ<p>…</p></div>`) จะกลับไปแปลทีละโหนดสำหรับข้อความนั้น หน้าที่มีโครงสร้างดีไม่เคยเจอกรณีนี้
- **แคชอยู่ในหน่วยความจำ** (ต่อเซสชันของแท็บ) การโหลดหน้าใหม่จะขอข้อความอีกครั้ง
- **PDF ไม่ถูกแปล** ตัวอ่าน PDF ในตัวไม่สามารถถูกควบคุมด้วยสคริปต์ของส่วนขยาย
- **โควตาฟรีเปลี่ยนได้** ขีดจำกัดอัตราและชื่อโมเดลกำหนดโดยผู้ให้บริการ ไม่ใช่ส่วนขยายนี้

## สถานะโปรเจกต์และการทดสอบ

เวอร์ชัน 1.3.1 ชุดทดสอบอัตโนมัติครอบคลุมชั้น DOM พรอมป์ต์และการแยกวิเคราะห์ รูปแบบคำขอของผู้ให้บริการ พฤติกรรมของเอนจิน และอินเทอร์เฟซตัวเลือก — **95 การทดสอบ** — และ `npm run verify` เพิ่มการตรวจสอบ 12 จุด: ไวยากรณ์ ชุดทดสอบ การห้ามจุดแทรก HTML การตรวจการรั่วของคีย์ content script แบบคลาสสิก ความสอดคล้องของเวอร์ชัน ความครอบคลุมของ CHANGELOG และการแพ็กเกจ

```bash
npm install       # สำหรับพัฒนาเท่านั้น: jsdom สำหรับการทดสอบ DOM
npm test          # 95 การทดสอบ
npm run bench     # วัดการแบ่งท่อน ไม่ต้องใช้คีย์ API
npm run verify    # ไวยากรณ์ + การทดสอบ + การตรวจสอบนโยบาย + การแพ็กเกจ
npm run package   # คัดลอกเฉพาะไฟล์ที่แจกจ่ายได้ไปยัง dist/
npm run release   # dist + release/*.zip, *.crx, *.pem สำหรับแจกจ่าย
```

การวัดนี้วัดการแบ่งท่อน ไม่ใช่วัดคุณภาพการแปล: บนหน้าตัวอย่างสี่หน้า ตัวเก็บโหนดข้อความอิสระสร้าง **108 ชิ้น** ขณะที่ตัวเก็บแบบบล็อกสร้าง **63 หน่วย** (น้อยกว่า 1.7 เท่าโดยรวม และ **2.5 เท่า** ในบทความข่าว) และชิ้นที่สั้นกว่า 25 อักขระลดจาก **81 เหลือ 34** คุณภาพการแปลยังขึ้นอยู่กับโมเดลที่คุณเชื่อมต่อ รายการตรวจด้วยมือใน [`TEST_CHECKLIST.md`](../../TEST_CHECKLIST.md) ครอบคลุมสิ่งที่การทดสอบอัตโนมัติไปไม่ถึง (การแสดงผล RTL ทูลทิป ทราฟฟิก SPA จริง และข้อผิดพลาดของผู้ให้บริการ)

CI รัน `npm run verify` และ `npm run bench` บน Node 20 และ 22 ทุก push และ pull request ([`.github/workflows/ci.yml`](../../.github/workflows/ci.yml))

## การมีส่วนร่วม

ยินดีรับ issue และ pull request ก่อนส่งการเปลี่ยนแปลง ให้รัน `npm run verify` รักษาส่วนขยายให้ไม่ต้อง build เก็บการรับส่งของผู้ให้บริการไว้ใน service worker และห้ามนำ `innerHTML` เข้ามา หากแก้พรอมป์ต์ ให้เพิ่มหรืออัปเดตการทดสอบ พรอมป์ต์ ตัวแยกวิเคราะห์ และตัวทำให้เป็นมาตรฐานถูกทดสอบร่วมกันเพราะทำงานได้เฉพาะเป็นชุดเดียว
