# AI Page Translator — 自分の AI でウェブを翻訳

AI Page Translator は **Brave** とその他の Chromium 系ブラウザー向けの拡張機能です。プロバイダーはご自身で用意します。無料の Google Gemini キー、OpenAI 互換の任意のエンドポイント（OpenRouter、Groq、NVIDIA、OpenAI…）、または **Ollama** による完全ローカルモデルです。拡張機能は読んでいるページをその場で翻訳し、レイアウト、リンク、書式を保ちます。

テキストが翻訳サービスを経由することはありません。API キーがブラウザーの外に出ることはなく、解析ツールもありません。Ollama を使えばテキストはお使いのコンピューターからも出ません。

> **状態：** バージョン 1.3.1 · 自動テスト 95 件 · 12 項目の検証 · テレメトリーなし、リモートコードなし。

---

## なぜもう一つの翻訳ツールなのか

ほとんどのページ翻訳ツールは一度に一文だけを送ります。そのため結果はページではなく文の寄せ集めのように読めます。文脈が失われ、用語がぶれ、リンクが文を真ん中で切り、対象言語が原文の語順を引き継いでしまいます。

この拡張機能はテキストノードではなく**ブロック**を翻訳します。

```
The <a>new privacy policy</a> takes effect <strong>immediately</strong>.
```

ブロックはひとつの単位として送られ、インラインのマークアップは番号付きトークンに置き換わります。

```
The <t1>new privacy policy</t1> takes effect <t2>immediately</t2>.
```

`<tN>…</tN>` は文に属するインライン内容（リンク、強調、span）を示し、`<vN/>` は決して翻訳してはいけない内容（コード、画像、フォーム部品、ウィジェット）を示します。モデルはトークンを移動できるため、英語の語順に縛られず、リンクの**周り**に自然な対象言語の文を組み立てられます。

戻ってきた答えは、ページに触れる前に検証されます。すべてのトークンが存在し、対応が取れ、重複がないことが必要です。リンクを落とした翻訳は拒否され、より厳しい指示で一度だけ再試行され、それでも駄目ならそのまま残されます。元の要素ノードを再利用するので、`href`、イベントリスナー、入れ子のマークアップはそのまま残ります。「原文を表示」は元のノードを正確に復元します。

## 機能

- **ページ全体をその場で翻訳** — 見出し、段落、リスト、表、キャプション、ボタン。
- **リンクとインライン書式を保持** — トークン検証付き。失われたリンクが黙って適用されることはありません。
- **自然な文体と直訳文体** — *自然*（既定）は母語話者の書き手のように書き直し、*直訳*は技術ページで原文の言い回しに近づけます。
- **言語別のスタイルガイド** — ペルシャ語、アラビア語、ウルドゥー語、ヘブライ語には専用の指針、残り 18 言語には共通の指針。
- **決定的な表記修正** — ペルシャ語の `ی`/`ک`、`می`/`ها`/`تر` のゼロ幅スペース、`، ؛ ؟` はモデルが間違えても修正されます。
- **任意の品質パス** — 各セグメントを {原文, 訳文} の組として読み、言い回しだけでなく意味も直します。
- **用語集** — モデルが守るべき「用語 → 訳語」の組。
- **保護された内容** — `<pre>`、`<code>`、URL、メールアドレス、`translate="no"`、`contenteditable`、SVG、フォーム部品、拡張機能自身の UI は決して送信されません。
- **属性ラベル** — `alt`、`title`、`placeholder`、`aria-label` は別チャンネルで、段落ではなくラベルの調子で翻訳されます。
- **動的なページ** — 無限スクロールや SPA で追加された内容は、現れ次第翻訳され、オブザーバーのループも起きません。
- **正しい右から左** — 翻訳したブロックごとに `dir`、`<html>` に `lang`。ページ全体を反転せず、すべて元に戻せます。
- **サイトごとの記憶** — ドメインごとの対象言語を覚え、読み込み時に自動翻訳できます。
- **API があるものは何でも** — Gemini、Ollama、OpenAI 互換の任意のエンドポイント。service worker から呼ぶので CORS の問題がありません。
- **メモリ内キャッシュ、再試行、分割** — 同じテキストは一度だけ送信。失敗したブロックはページ全体を失敗させずに分割。429/5xx は待ち時間を増やして再試行。
- **ビルド不要** — 素のクラシックスクリプトをそのまま読み込みます。

## インストール

1. このリポジトリをダウンロードし（**Code → Download ZIP** または `git clone`）、フォルダーを保管します。
2. `brave://extensions`（または `chrome://extensions`）を開きます。
3. **デベロッパーモード**をオンにします。
4. **Load unpacked** を押し、このフォルダー（`manifest.json` がある場所）を選びます。
5. ポップアップをワンクリックで使いたい場合は拡張機能をピン留めします。

ビルド、インストール、バンドルの手順はありません。拡張機能は `manifest.json` に列挙されたファイルだけを読みます。`tests/`、`scripts/`、`bench/`、`docs/`、`.github/` は開発専用で、決して読み込まれません。

最新の Chromium 系ブラウザーが必要です。閉じた shadow root はブラウザーが API を公開している場合（Chromium 119 以降）に翻訳されます。それ以外は古いバージョンでも動作します。

## 他の人への配布

`npm run release` はパッケージをビルドし、`release/` にファイルを出力します（git では無視されます）。

| ファイル | 内容 | インストール方法 |
|---|---|---|
| `page-translator-ai-<version>.zip` | 拡張機能全体、約 95 KB、中に `INSTALL.txt` | 展開して **Load unpacked**。ストアが受け付けるのも同じファイルです |
| `page-translator-ai-<version>.crx` | 署名済みパッケージ | ストア外のインストールが許可されている `brave://extensions` にドラッグ |
| `page-translator-ai-signing-key.pem` | 署名鍵 | 決して共有しないでください。`npm run release` が再利用するので、更新しても拡張機能 ID が変わりません |

つまり渡すものは 1 つのファイルで、その中にインストール手順が入っています。

**正直な制限：** ブラウザー拡張機能はクライアント側のコードです。インストールした人はそのファイルを読めます。`.crx` は署名済み zip、展開した拡張機能はただのフォルダーです。パッケージ化や難読化で変わるものではありません。縮小は読む速度を落とすだけで、ストアのポリシーは難読化を禁じています。ソースを本当に秘密にするなら、プロンプトとプロバイダー呼び出しを自分で管理するサーバーへ移すしかなく、それは「自分のキーで、バックエンドなし」という設計を捨てることになります。

リポジトリを渡さずに配布するには、zip を Chrome ウェブストアの**非公開または限定公開**の項目として公開してください。技術者でない利用者にとって、ワンクリックでインストールできる唯一の方法です。

## プロバイダーの設定

拡張機能のポップアップ → **Options & settings**、または `brave://extensions` → 詳細 → 拡張機能のオプション。

| プロバイダー | エンドポイント | キー | 備考 |
|---|---|---|---|
| **Ollama**（ローカル） | `http://localhost:11434` | 不要 | 無料で完全にプライベート。[ollama.com](https://ollama.com) からインストールし、`ollama run llama3` を実行します。403 が返る場合は `OLLAMA_ORIGINS=chrome-extension://*` を付けて再起動してください。 |
| **Google Gemini** | `generativelanguage.googleapis.com` | [AI Studio](https://aistudio.google.com/app/apikey) の無料キー | `gemini-2.5-flash` など現在のモデル ID を使います。無料枠は変わるので Google のモデル一覧を確認してください。 |
| **OpenAI 互換** | 任意のエンドポイント（例：`https://openrouter.ai/api/v1`、`https://api.groq.com/openai/v1`、`https://integrate.api.nvidia.com/v1`） | プロバイダーのキー | `/chat/completions` を話すサービスなら何でも。UI のモデル候補は例なので、プロバイダーのカタログにある正確な ID を使ってください。 |

次に：

1. **既定の対象言語**を選びます。
2. **翻訳スタイル**を選びます。*Natural*（推奨）または *Literal*。
3. 必要なら **Quality mode** をオンにし、**用語集**を 1 行 1 件で追加します（`用語 → 訳語`。`->`、`=>`、`=`、TAB も使えます）。
4. **原文の言語**を *Auto-detect* のままにするか、明示的に選びます。
5. **Test connection** を押し、続いて **Save settings** を押します。

プロバイダーに関する注意：

- **Gemini の思考設定はモデル世代ごとに選ばれます。** 2.5 Flash と Flash-Lite は思考なし、2.5 Pro は最小予算（128）、3.x/4.x は低いレベルです。モデルが設定を拒否した場合、その設定なしで一度だけ再試行します。
- **Ollama** は 8192 トークンのコンテキストウィンドウで呼び出します。それ未満で学習したモデルは長いページを切り詰めるため、ページを小さな単位に分割しています。
- **無料枠**にはレート制限があります。拡張機能は待って再試行し、テキストを黙って捨てることはありません。

## 使い方

- アイコンをクリック → 言語を選ぶ → **Translate this page**。
- **Show original / Show translation** はいつでも。復元は無損失です。
- 翻訳された段落にカーソルを合わせると原文を確認できます。
- 右クリック → **Translate this page** または **Translate selection**。
- キーボード：`Ctrl+Shift+Y`（macOS は `Cmd+Shift+Y`）で翻訳を切り替え。ブラウザーの拡張機能ショートカット画面で変更できます。
- **Auto-translate** がオンでサイト設定が保存されていれば、該当ページは読み込み時に自動翻訳されます。
- 設定は次回の翻訳から開いているタブに適用されます。再読み込みは不要です。

## 仕組み

```
ページの DOM
  └─ content script: ブロック単位を集め、インラインのマークアップを <tN>/<vN/> トークンに変換
       └─ 分割器: リクエストあたり 24 単位 / 2400 文字
            └─ service worker: プロバイダーへリクエスト（拡張機能のオリジン、CORS なし）
                 └─ プロバイダー: JSON 入力、JSON 出力、ID は保持
                      └─ 検証: トークンが完全・対応・一意、ID が一致
                           └─ DOM: 元の要素ノードを再利用し、テキストだけを書き込む
                                └─ MutationObserver: 後から追加された内容を翻訳
```

本当に重要な設計判断：

- **プロバイダーへの通信はページのコンテキストから出ません。** content script が `AIPT_FETCH` メッセージを送り、service worker がリクエストを行います。そのため CORS が厳しいエンドポイントもそのまま動きます。service worker は `sender.id` も確認するので、この拡張機能だけがプロキシとして使えます。
- **プロンプトは願いではなく契約です。** ID を入れて ID を返す。セグメントごとに 1 件。タグは不可触。数値、URL、コード、プレースホルダーはそのまま。説明の追加はなし。応答は ID で読むので、並べ替えられた配列や一部壊れた配列は、訳をずらすのではなく安全に失敗します。
- **言語ごとにスタイルガイドがあります。** たとえばペルシャ語のガイドはペルシャ語の語順と動詞を求め（`بررسی کنید`、`بررسی را انجام دهید` ではない）、普通の文で足りるところでは `می‌باشد`/`بایستی`/`گردید` を禁じ、ラテン文字は本当の借用語だけに残し、句読点とゼロ幅スペースを直します。few-shot の例は目標を説明するのではなく見せます。
- **方向はローカルです。** ペルシャ語、アラビア語、ヘブライ語、ウルドゥー語のブロックには `dir="rtl"`、`<html>` には対象言語を設定し、ページの残りは配置を保ちます。ページ全体の反転は中央寄せのレイアウトやコードブロックを壊していました。どちらも原文とともに復元されます。
- **失敗は見え、範囲も限られます。** 解析できないブロックは分割されます。それでも失敗する単位は原文のまま残り、上部のバナーで報告されます。翻訳中のキャンセルはきれいに止まり、書きかけの DOM を残しません。

詳しくは [`docs/translation-quality-design.md`](../translation-quality-design.md)。

## プライバシーと権限

| 権限 | 必要な理由 |
|---|---|
| `storage` | 設定、API キー、用語集、サイトごとの設定を `chrome.storage.local` に保存します。 |
| `contextMenus` | 右クリックの「このページ / 選択範囲を翻訳」。 |
| `tabs` | アクティブなタブへメッセージを送り、オプションを開きます。 |
| `activeTab` | 明示的に翻訳するページで動作します。 |
| `<all_urls>` | 訪問したページに content script を注入し、service worker が設定したエンドポイントを呼べるようにします。 |

- API キーはこのブラウザーのローカルストレージにのみ保存され、選んだプロバイダーにだけ送信されます。
- 解析ツール、テレメトリー、リモートコード、開発者サーバーへの通信、アカウントはありません。
- すべてのテキストは `textContent` / `createTextNode` で書き込みます。`innerHTML`、`eval`、`new Function` はどこにもありません。モデルの出力はテキストとしてしかページに届かず、属性は固定の許可リストに限られます。`href`、`src`、イベントハンドラーがモデル出力から書かれることはありません。
- サイトごとの設定は service worker の単一の直列化ライターが書くので、2 つのタブが互いを上書きしません。
- 言語の自動判定は同じプロバイダーへ最大 600 文字のサンプルを送ります。原文の言語を手動で選べば、このリクエスト自体がなくなります。

セキュリティポリシーと脆弱性の報告：[`SECURITY.md`](../../SECURITY.md)。

## 既知の制限

- **トークン検証は意図的に厳格です。** `<tN>` を壊し続けるモデルは、リンクを失う代わりにその段落を原文のまま残し、その旨を表示します。構造化出力に従うモデルを使ってください。*Test connection* はトークン付きの文を試します。
- **品質はモデル次第です。** 小さなローカルモデルは使えますが、Gemini や GPT クラスほど流暢ではありません。スタイル層は助けになりますが、知識は増やしません。
- **閉じた shadow root と cross-origin iframe** は拡張機能の範囲外です（ブラウザーのセキュリティ）。開いた shadow root と同一オリジンのフレームは扱えます。
- **ゆるいテキストを含む混在コンテナー**（`<div>テキスト<p>…</p></div>`）は、そのテキストについてノード単位の翻訳に戻ります。整ったページでは起きません。
- **キャッシュはメモリ内**（タブのセッションごと）。ページを再読み込みするとテキストを再要求します。
- **PDF は翻訳されません。** 内蔵 PDF ビューアーは拡張機能からスクリプトで操作できません。
- **無料枠は変わります。** レート制限とモデル名はプロバイダーが決めるもので、この拡張機能ではありません。

## プロジェクトの状態とテスト

バージョン 1.3.1。自動テストは DOM 層、プロンプトと解析、プロバイダーごとのリクエスト形式、エンジンの挙動、オプション画面をカバーし、**95 件**あります。`npm run verify` はさらに 12 項目の検証を行います：構文、テストスイート、HTML シンクの禁止、キー漏えい、クラシックな content script、バージョン一致、CHANGELOG の記載、パッケージング。

```bash
npm install       # 開発用のみ：DOM テスト用の jsdom
npm test          # 95 件のテスト
npm run bench     # 分割のベンチマーク、API キー不要
npm run verify    # 構文 + テスト + ポリシー検査 + パッケージ検査
npm run package   # 配布可能なファイルだけを dist/ にコピー
npm run release   # dist と release/*.zip、*.crx、*.pem を生成
```

ベンチマークが測るのは分割であり、翻訳品質ではありません。4 つのサンプルページで、独立したテキストノード収集器は **108 個の断片**を作り、ブロック収集器は **63 単位**を作ります（全体で 1.7 倍少なく、ニュース記事では **2.5 倍**）。25 文字未満の断片は **81 から 34** に減ります。翻訳品質そのものは接続するモデル次第です。自動テストが届かないブラウザー上の挙動（RTL 表示、ツールチップ、実際の SPA 通信、プロバイダーのエラー）は [`TEST_CHECKLIST.md`](../../TEST_CHECKLIST.md) の手動チェックリストにあります。

CI は push と pull request のたびに Node 20 と 22 で `npm run verify` と `npm run bench` を実行します（[`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)）。

  translation-engine.js       キャッシュ、分割、並列、再試行、二分分割、品質パス
  dom-processor.js            ブロック単位、トークン、検証済み適用、正確な復元、方向
  content-script.js           全体調整、状態、メッセージング、自動翻訳
  styles.css                  RTL に本当に必要な 2 つのルール
popup/                       言語選択、翻訳/復元、進捗、エラー

## コントリビュート

issue と pull request を歓迎します。変更を送る前に `npm run verify` を実行してください。拡張機能はビルド不要のままにし、プロバイダーへの通信は service worker に置き、`innerHTML` を決して導入しないでください。プロンプトを変えたらテストを追加または更新してください。プロンプト、パーサー、正規化器はひとまとまりでしか機能しないため、一緒にテストします。

完全なルール、`docs/i18n/` の翻訳ポリシー、コミットの慣習は [`CONTRIBUTING.md`](../../CONTRIBUTING.md) にあります。
